# ADR 0003：由订阅计划授予服务权限

- 状态：已接受
- 日期：2026-09-16

## 背景

服务可见性不能直接耦合到某个计划名称或等级。AccessHub 后续还会接入更多服务、资源类型与支付渠道，因此需要稳定的授权抽象，同时保留 API Key 自身的服务范围约束。

## 决策

1. `Permission` 表示稳定能力，以可读编码唯一标识。
2. `Plan Permission Grant` 显式连接订阅计划与权限。
3. 服务可以不设访问要求，也可以引用一项必需权限。
4. 普通用户的有效权限为默认计划与全部当前有效计划授权的并集；管理员隐式拥有全部权限。
5. 服务目录和网关执行使用同一权限解析逻辑。无权限的服务不展示，直接调用返回 `403 permission_denied`。
6. API Key Scope 仍是独立的凭据约束。一次调用必须同时通过 API Key Scope 与用户权限校验。

## 结果

- 新增服务或订阅计划时无需改写授权代码，只需组合权限与授权关系。
- 不根据计划名称、价格或阶梯位置推断能力。
- 默认计划可以授予所有登录用户均可用的基础能力。
- 未来其他资源可复用 Permission，但多权限表达式、拒绝规则和组织级角色不在本次范围内。
